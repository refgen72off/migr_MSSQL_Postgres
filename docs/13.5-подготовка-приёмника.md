# 13.5 Подготовка приёмника (Tantor 18)

Инструкция к этапу 5 плана. Результат этапа: Tantor 18 развёрнут, создана отдельная БД в `UTF8` с
выбранной локалью, схема(ы), роль миграции и отдельный пользователь приложения с минимальными
правами; бэкап и мониторинг настроены; подключение проверено с двух хостов — приложения и
pgloader.

`postgres` и `sa` в работах не используются: у `postgres` остаются только административные
функции, вся миграция идёт под отдельными ролями.

## 1. Проверить установку Tantor 18

Пути и имена служб зависят от редакции и версии — сверить с документацией Tantor для своей
сборки (в материалах по миграции с PG 15 используются `/opt/tantor/db/18/bin`,
`/var/lib/postgresql/tantor-certified-18/data`, служба `tantor-certified-server-18.service`).

```bash
sudo -u postgres /opt/tantor/db/18/bin/postgres --version
systemctl status tantor-*-18.service --no-pager
ls -l /opt/tantor/db/18/bin/{psql,pg_dump,pg_restore,vacuumdb,pg_amcheck}
```

Если экземпляр ещё не инициализирован — `initdb` с нужными параметрами (одна из двух форм):

```bash
# ICU-локаль (рекомендуется для кириллицы и предсказуемой сортировки)
sudo -u postgres /opt/tantor/db/18/bin/initdb \
  -D /var/lib/postgresql/tantor-certified-18/data \
  --encoding=UTF8 --locale-provider=icu --icu-locale=ru-RU --data-checksums

# libc-локаль (если политика требует локали ОС)
sudo -u postgres /opt/tantor/db/18/bin/initdb \
  -D /var/lib/postgresql/tantor-certified-18/data \
  --encoding=UTF8 --locale=ru_RU.UTF-8 --data-checksums
```

Контрольные суммы (`--data-checksums`) включаются сразу: включить их позже нельзя без переписывания
кластера, а наличие проверки страниц — единственный способ поймать тихое повреждение на диске.

Проверка после старта:

```bash
sudo -u postgres /opt/tantor/db/18/bin/psql -c "select version();"
sudo -u postgres /opt/tantor/db/18/bin/psql -c "show data_checksums;"
sudo -u postgres /opt/tantor/db/18/bin/psql -c "show server_encoding;"
```

## 2. Создать базу и схемы

```sql
-- под ролью с правом CREATEDB (не postgres в проде, но на этапе создания это администратор)
CREATE DATABASE target_db
    WITH OWNER = postgres
         ENCODING = 'UTF8'
         LOCALE_PROVIDER = icu
         ICU_LOCALE = 'ru-RU'
         TEMPLATE = template0;
```

Параметры локали (`LOCALE_PROVIDER`, `ICU_LOCALE`, `BUILTIN_LOCALE`, `LOCALE`) появились в
PostgreSQL 16–18 и отличаются между версиями — сверить `\h CREATE DATABASE` в своей сборке перед
запуском. Смена провайдера локали после загрузки означает переиндексацию, поэтому решение
принимается один раз.

Схемы и роли:

> Порядок важен: если `password_encryption` задаётся в этом документе позже (раздел 3), то на
> свежем Tantor 18 (PG 14+) он и так по умолчанию `scram-sha-256` — создаваемые здесь пароли уже
> будут scram. Для более старых или переконфигурированных кластеров настройку применить **до**
> `CREATE ROLE`.

```sql
\c target_db

-- в PG15+ схема public больше не даёт CREATE роли PUBLIC по умолчанию; закрываем явно.
-- Отзываем только CREATE: USAGE у PUBLIC оставляем — он нужен ролям для вызова функций
-- расширений (citext, pg_trgm, unaccent — см. ниже)
REVOKE CREATE ON SCHEMA public FROM PUBLIC;

CREATE ROLE migr_etl LOGIN PASSWORD :'migr_pwd';   -- пароль подставляет psql -v, не в истории
CREATE ROLE app_rw  LOGIN PASSWORD :'app_pwd';

CREATE SCHEMA app AUTHORIZATION migr_etl;          -- схема принадлежит роли миграции
CREATE SCHEMA IF NOT EXISTS staging AUTHORIZATION migr_etl;

GRANT CONNECT ON DATABASE target_db TO migr_etl, app_rw;
GRANT USAGE, CREATE ON SCHEMA app     TO migr_etl;
GRANT USAGE, CREATE ON SCHEMA staging TO migr_etl;

-- приложению — только работа с данными, без DDL
GRANT USAGE ON SCHEMA app TO app_rw;
GRANT SELECT, INSERT, UPDATE, DELETE ON ALL TABLES IN SCHEMA app TO app_rw;
GRANT USAGE, SELECT ON ALL SEQUENCES IN SCHEMA app TO app_rw;

-- чтобы будущие объекты, созданные миграцией, тоже были доступны приложению
ALTER DEFAULT PRIVILEGES FOR ROLE migr_etl IN SCHEMA app
    GRANT SELECT, INSERT, UPDATE, DELETE ON TABLES TO app_rw;
ALTER DEFAULT PRIVILEGES FOR ROLE migr_etl IN SCHEMA app
    GRANT USAGE, SELECT ON SEQUENCES TO app_rw;
```

Примечания к исполнению: `ALTER DEFAULT PRIVILEGES FOR ROLE migr_etl` выполняется от самой
`migr_etl` либо суперпользователя/члена роли (иначе ошибка `must be member of role`). Шаги
`CREATE DATABASE`, `CREATE EXTENSION` и настройка конфигурации — административные, выполняются
админ-ролью кластера; это единственное осознанное исключение из правила «`postgres` не
используется».

Смысл разделения: `migr_etl` создаёт таблицы, индексы и ограничения (владелец объектов), `app_rw`
работает только с данными, `postgres` не участвует. Права `SUPERUSER`, `CREATEROLE`, `CREATEDB`
роли миграции не выдаются.

Проверка, что прав ровно столько, сколько нужно:

```sql
\c target_db migr_etl
CREATE TABLE app._perm_check (id integer);   -- должно пройти
DROP TABLE app._perm_check;

\c target_db app_rw
CREATE TABLE app._perm_check (id integer);   -- должно УПАСТЬ: у приложения нет CREATE
CREATE TABLE public._perm_check (id integer); -- тоже должно УПАСТЬ: в public CREATE отозван
```

## 3. Доступ по сети и аутентификация

```conf
# pg_hba.conf — только нужные хосты, только scram
# TYPE  DATABASE    USER        ADDRESS           METHOD
host    target_db   migr_etl    10.10.20.15/32    scram-sha-256
host    target_db   app_rw      10.10.30.0/24     scram-sha-256
host    all         postgres    127.0.0.1/32      scram-sha-256
```

```sql
ALTER SYSTEM SET password_encryption = 'scram-sha-256';
SELECT pg_reload_conf();

ALTER SYSTEM SET listen_addresses = '10.10.20.10';
```

```bash
sudo systemctl restart tantor-*-18.service
```

`listen_addresses` применяется только рестартом службы — `reload` на него не действует, и без
рестарта проверки подключения с удалённых хостов уйдут в таймаут. `password_encryption`
перечитывается по `reload` и действует на `CREATE ROLE`/`ALTER ROLE ... PASSWORD`, выполняемые
после него.

Проверки:

```bash
# с хоста pgloader
psql "host=10.10.20.10 port=5432 dbname=target_db user=migr_etl sslmode=prefer" -c "select current_user, current_database();"
# с хоста приложения
psql "host=10.10.20.10 dbname=target_db user=app_rw" -c "select 1;"
```

Если `pg_hba` задан списком, порядок строк решает: более общая строка `host all all ...` выше
конкретной перекроет её. Проверяется реальным подключением, а не чтением файла.

## 4. Настройки под загрузку

Параметры применяются на время загрузки и возвращаются к штатным после (13.9).

```sql
ALTER SYSTEM SET maintenance_work_mem = '2GB';       -- построение индексов
ALTER SYSTEM SET max_wal_size = '8GB';               -- меньше чекпоинтов на загрузке
ALTER SYSTEM SET checkpoint_timeout = '15min';
ALTER SYSTEM SET wal_compression = 'lz4';            -- PG15+
ALTER SYSTEM SET log_min_duration_statement = '5s';  -- видно тяжёлые запросы после переключения
ALTER SYSTEM SET jit = 'off';                        -- на загрузке JIT только мешает
SELECT pg_reload_conf();
```

`work_mem` не меняется глобально: он задаётся в загрузочном файле pgloader (`SET work_mem to
'64MB'`) — глобально высокий `work_mem` при большом числе соединений съедает память.

`autovacuum` для загружаемых таблиц: ручного окна «между созданием схемы и загрузкой» нет —
таблицы создаёт сам pgloader тем же прогоном. Отключение делается средствами pgloader (13.7):
клауза `ALTER TABLE NAMES MATCHING ~/./ IN SCHEMA 'app' SET (autovacuum_enabled = false)`
превращается в `WITH (...)` при `CREATE TABLE` каждой таблицы. После загрузки — обратно `true`
плюс `ANALYZE` (13.9). На пустых таблицах autovacuum бесполезен, а на загрузке добавляет шум
и I/O.

`fsync`/`synchronous_commit` на время загрузки отключать **не рекомендуется** без письменного
согласования: цель перезаливается, но падение сервера в этот момент оставит кластер в состоянии,
требующем восстановления из копии.

## 5. Расширения и объекты, нужные заранее

```sql
CREATE EXTENSION IF NOT EXISTS pg_stat_statements;   -- требует shared_preload_libraries
CREATE EXTENSION IF NOT EXISTS citext;               -- регистронезависимые текстовые колонки
CREATE EXTENSION IF NOT EXISTS pg_trgm;              -- поиск по подстроке, LIKE '%...%'
CREATE EXTENSION IF NOT EXISTS unaccent;             -- если приложение ищет без диакритики
CREATE EXTENSION IF NOT EXISTS amcheck;              -- проверка индексов (13.3, 13.9)
```

`gen_random_uuid()` входит в ядро с PG 13 — расширение `pgcrypto` для этого не нужно.
PostGIS и прочие расширения, не входящие в поставку Tantor, ставятся отдельно и проверяются на
совместимость с версией ядра (этот пункт фиксируется в `compatibility.md`).

`shared_preload_libraries` меняется только через рестарт:

```sql
ALTER SYSTEM SET shared_preload_libraries = 'pg_stat_statements';
-- затем: systemctl restart tantor-*-18.service
```

## 6. Бэкап и мониторинг (рекомендация)

Бэкап и мониторинг на приёмнике настраиваются администратором стенда отдельно; задача миграции
их не разворачивает (для тестовых стендов допустимо отложить до рабочей базы). Что желательно
сделать до переключения приложения:

- **Бэкап** Tantor DB (штатное средство Tantor или pgBackRest) — до загрузки данных, а не после;
  проверка — полная копия и тестовое восстановление в отдельный кластер (по той же логике,
  что 13.2).
- **WAL-архив**: если требуется PITR — `archive_mode = on`, `archive_command` на внешний том.
- **Мониторинг**: подключить экземпляр к системе мониторинга до переключения приложения.
  Минимум: доступность, `pg_stat_activity` (долгие запросы), `pg_stat_database` (temp files,
  bloat-намёки), свободное место, задержка реплик (если есть).
- **Алерты**: `temp_file_limit`, заполнение диска, долгие транзакции (`idle in transaction`),
  ошибки в логе.

Отступления для тестового стенда (широкий `pg_hba`, отсутствие бэкапа/мониторинга) фиксируются
в протоколе этапа.

## 7. Фиксация параметров

Выгрузка фактических значений — вход для протокола и для сравнения со стендом:

```sql
-- lc_collate/lc_ctype как GUC удалены в PG 18 (unrecognized configuration parameter) —
-- локали берутся из pg_database (datcollate/datctype; ICU-локаль в PG 18 — datlocale,
-- в старых версиях — daticulocale)
SELECT name, setting, unit, source FROM pg_settings
WHERE name IN ('server_encoding','data_checksums',
               'work_mem','maintenance_work_mem','max_wal_size','wal_compression',
               'password_encryption','fsync','synchronous_commit','jit',
               'shared_preload_libraries','wal_level','max_wal_senders','archive_mode')
ORDER BY name;

SELECT datname, pg_encoding_to_char(encoding), datcollate, datctype, datlocprovider, datlocale
FROM pg_database WHERE datname = current_database();

SELECT version(), current_setting('server_version_num');
```

## Готово, когда

- [ ] экземпляр Tantor 18 отвечает, `data_checksums = on`, кодировка `UTF8`;
- [ ] БД создана из `template0` с зафиксированным провайдером локали;
- [ ] схемы созданы, владелец — роль миграции;
- [ ] роли `migr_etl` и `app_rw` созданы, пароли не хранятся в истории и в репозитории;
- [ ] проверка прав выполнена: миграция может создавать объекты, приложение — нет;
- [ ] `pg_hba.conf` пускает только нужные хосты, метод `scram-sha-256`;
- [ ] подключение проверено с хоста pgloader и с хоста приложения;
- [ ] параметры загрузки применены, `shared_preload_libraries` требует рестарта — рестарт сделан;
- [ ] расширения, нужные приложению, установлены;
- [ ] бэкап настроен и проверен восстановлением, мониторинг видит экземпляр;
- [ ] выгрузка `pg_settings` сохранена в протокол.

## Типичные ошибки

| Симптом | Причина | Что делать |
|---|---|---|
| `permission denied for schema app` | схема принадлежит другой роли или нет `CREATE` | `CREATE SCHEMA ... AUTHORIZATION migr_etl`, `GRANT USAGE, CREATE` |
| приложение после загрузки не видит таблиц | объекты созданы миграционной ролью, гранты не выданы | `ALTER DEFAULT PRIVILEGES` + разовый `GRANT ... ON ALL TABLES` |
| `no pg_hba.conf entry for host` | не добавлен хост pgloader/приложения | строка в `pg_hba.conf` + `reload` |
| `password authentication failed` | пароль создан с `md5`, в `pg_hba` — `scram` | `password_encryption = 'scram-sha-256'` до смены пароля |
| `initdb: invalid locale name` | локаль ОС отсутствует | `locale -a`, установить пакет локалей или использовать ICU |
| `unrecognized configuration parameter "lc_collate"` | GUC-параметры локали удалены в PG 18 | брать локали из `pg_database` (`datcollate`/`datctype`/`datlocale`) |
| `column "daticulocale" does not exist` | в PG 18 колонка переименована | использовать `datlocale` |
| `could not create unique index` при загрузке | данные нарушают уникальность | `NOT VALID`/разбор данных, не отключать ограничение навсегда |
| загрузка «съела» весь диск | `max_wal_size`/архив не рассчитаны | контроль места, `archive_command` на внешний том, `pg_stat_wal` |
| экземпляр «задумался» на загрузке | `jit = on`, чекпоинты, autovacuum | параметры раздела 4 |
| приложение падает на `could not serialize access` | уровень изоляции выше, чем в MSSQL | согласовать уровни с приложением (13.12), не «лечить» повтором |

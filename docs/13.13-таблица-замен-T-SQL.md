# 13.13 Приложения: таблица «конструкция T-SQL → замена в PostgreSQL»

Инструкция к этапам 4 и 12 плана. Результат: справочник замен для разработчика, рабочий список
объектов с найденными конструкциями и статусом переноса, критерии проверки переписанного кода.

## 1. Как пользоваться

1. Инвентарь (13.1) даёт список объектов, 13.4 — частоты конструкций.
2. По каждому объекту заполняется строка рабочего списка (раздел 2) с найденными конструкциями.
3. Разработчик переписывает объект, сверяясь с таблицей раздела 3.
4. Объект считается перенесённым, когда: создан в PostgreSQL, вызывается приложением и прошёл
   проверку раздела 5.

Таблица замен — не учебник, а чек-лист: если конструкция в коде не встречается, её строка не нужна.

## 2. Рабочий список объектов

```sql
-- 50-object-worklist.sql
SELECT s.name AS schema_name, o.name AS object_name, o.type_desc,
       LEN(m.definition) AS chars, o.modify_date
FROM sys.objects o
JOIN sys.schemas s     ON s.schema_id = o.schema_id
JOIN sys.sql_modules m ON m.object_id = o.object_id
WHERE o.is_ms_shipped = 0 AND o.type IN ('P','PC','FN','IF','TF','TR','V')
ORDER BY chars DESC;
```

Результат переносится в файл вне репозитория (имена объектов заказчика) со столбцами:

| Объект | Тип | Найденные конструкции | Ответственный | Статус | Проверено на стенде |
|---|---|---|---|---|---|
| `dbo.OrderRecalc` | P | `MERGE`, `TRY/CATCH`, `SCOPE_IDENTITY` | | в работе | нет |

Статусы: `не начат` → `в работе` → `создан` → `проверен`. «Создан» без «проверен» не считается
готовым к переключению.

## 3. Таблица замен

### 3.1. Выборка и соединения

| T-SQL | PostgreSQL | Замечание |
|---|---|---|
| `SELECT TOP 10 ...` | `SELECT ... LIMIT 10` | без `ORDER BY` результат не определён в обеих СУБД |
| `ORDER BY ... OFFSET 20 ROWS FETCH NEXT 10 ROWS ONLY` | `... ORDER BY ... LIMIT 10 OFFSET 20` | синтаксис `OFFSET/FETCH` тоже поддерживается |
| `CROSS APPLY` / `OUTER APPLY` | `CROSS JOIN LATERAL` / `LEFT JOIN LATERAL ... ON true` | основная замена табличных функций |
| `WITH (NOLOCK)` | убрать | грязных чтений нет; при нужде — `READ COMMITTED` и так не блокирует читателей |
| `WITH (UPDLOCK, ROWLOCK)` | `SELECT ... FOR UPDATE` | блокировка строки до конца транзакции |
| `WITH (READPAST)` | `SELECT ... FOR UPDATE SKIP LOCKED` | очереди и «захват задания» |
| `OPTION (MAXDOP 1)`, `RECOMPILE` | нет прямого аналога | `SET LOCAL max_parallel_workers_per_gather = 0` |
| `SELECT ... INTO #t` | `CREATE TEMP TABLE ... AS SELECT` | живёт до конца сессии/транзакции |
| `PIVOT` / `UNPIVOT` | условная агрегация (`sum(...) FILTER`, `CASE`) или `crosstab` | расширение `tablefunc` |
| `FOR XML PATH('')` (склейка строк) | `string_agg(col, ',' ORDER BY ...)` | классическая замена «склейки» |
| `FOR JSON PATH` | `jsonb_agg(jsonb_build_object(...))` | далее `->>`/`#>` для выборки |
| `OPENJSON` | `jsonb_to_recordset`, `jsonb_array_elements` | |
| `ISJSON(x) = 1` | `x IS JSON` (PG 16+) или `pg_input_is_valid` | |
| `db.schema.table` | нет | `postgres_fdw`/`dblink` либо перенос логики в приложение |
| `OPENQUERY`, `OPENROWSET` | `postgres_fdw`, `dblink`, внешние таблицы | отдельный проект |

### 3.2. Строки и NULL

| T-SQL | PostgreSQL | Замечание |
|---|---|---|
| `ISNULL(a,b)` | `coalesce(a,b)` | |
| `a + b` (строки) | `a \|\| b` | `+` для чисел остаётся `+` |
| `LEN(s)` | `length(rtrim(s))` | `LEN` не считает хвостовые пробелы, `length` считает |
| `DATALENGTH(s)` | `octet_length(s)` | |
| `CHARINDEX(sub, s)` | `strpos(s, sub)` | порядок аргументов обратный! |
| `PATINDEX('%[0-9]%', s)` | `substring(s from '[0-9]+')` | регулярные выражения |
| `SUBSTRING(s, start, len)` | `substring(s from start for len)` | 1-based в обеих СУБД |
| `LEFT(s,n)`, `RIGHT(s,n)` | `left(s,n)`, `right(s,n)` | |
| `STUFF(s, start, len, repl)` | `overlay(s placing repl from start for len)` | |
| `REPLICATE(s,n)` | `repeat(s,n)` | |
| `LTRIM`/`RTRIM` | `btrim(s)`, `ltrim`, `rtrim` | в PG 18 `ltrim`/`rtrim` тоже есть |
| `QUOTENAME(x)` | `quote_ident(x)` | для идентификаторов, не для литералов |
| `N'текст'` | `'текст'` | Unicode в PG — всегда; `E''` только для escape-последовательностей |
| `LIKE` (регистронезависимо из-за collation) | `LIKE` (регистрозависимо) или `ILIKE` | решение фиксируется по колонке |
| `COLLATE Latin1_General_CI_AS` | `COLLATE "ru-RU-x-icu"` или `citext` | |
| `CONCAT(a,b)` | `concat(a,b)` | `concat` игнорирует NULL, `\|\|` — нет |
| `FORMAT(x, 'N2')` | `to_char(x, 'FM999G999D00')` | локаль и разделители настраиваются |
| `STRING_AGG(x, ',')` | `string_agg(x, ',')` | порядок задаётся `ORDER BY` внутри агрегата |

### 3.3. Даты и время

| T-SQL | PostgreSQL | Замечание |
|---|---|---|
| `GETDATE()` | `now()` | `now()` — начало транзакции |
| `SYSDATETIME()` | `clock_timestamp()` | фактическое время в момент вызова |
| `GETUTCDATE()` | `now() AT TIME ZONE 'UTC'` | тип результата — `timestamp` без зоны |
| `DATEADD(day, -1, d)` | `d - interval '1 day'` | |
| `DATEDIFF(day, a, b)` | `b::date - a::date` | для дней; для прочих единиц — `extract(epoch ...)/...` |
| `DATEPART(year, d)` | `extract(year from d)` | `week` считается по-разному, проверить |
| `DATENAME(month, d)` | `to_char(d, 'TMMonth')` | зависит от локали сессии |
| `DATEFROMPARTS(y,m,d)` | `make_date(y,m,d)` | |
| `EOMONTH(d)` | `(date_trunc('month', d) + interval '1 month - 1 day')::date` | |
| `CONVERT(varchar, d, 104)` | `to_char(d, 'DD.MM.YYYY')` | таблица стилей → шаблон `to_char` |
| `ISDATE(s) = 1` | `pg_input_is_valid(s, 'date')` (PG 16+) | |
| `SWITCHOFFSET` | `AT TIME ZONE` | |
| `date_bin`/группировка по 15 мин | `date_bin('15 minutes', ts, '2000-01-01')` | PG 14+ |

### 3.4. Числа и типы

| T-SQL | PostgreSQL | Замечание |
|---|---|---|
| `CAST(x AS int)` | `x::integer` | `::` короче, но в динамическом SQL читаемее `CAST` |
| `TRY_CAST(x AS int)` | `pg_input_is_valid(x,'int')` + `CAST` | PG 16+ |
| `ISNUMERIC(x)` | `x ~ '^-?[0-9]+(\.[0-9]+)?$'` | `ISNUMERIC` в MSSQL пропускает `1e5`, `+`, `$` |
| `ROUND(x, 2)` | `round(x, 2)` | `numeric` округляет половину от нуля; `float` — как в IEEE |
| `CEILING`, `FLOOR` | `ceil`, `floor` | |
| `SQUARE(x)` | `x*x` | |
| `POWER(x,y)` | `power(x,y)` → `^` | `^` — возведение в степень в PG |
| `HASHBYTES('SHA2_256', x)` | `sha256(convert_to(x,'UTF8'))` | функция `sha256` в PG 14+ |
| `CHECKSUM(x)`, `BINARY_CHECKSUM(*)` | `hashtextextended(x::text, 0)` | значения не совпадут с MSSQL — только для внутренней сверки |
| `IDENT_CURRENT('dbo.T')` | `last_value` из `pg_sequences` / `pg_get_serial_sequence` | |

### 3.5. Изменение данных

| T-SQL | PostgreSQL | Замечание |
|---|---|---|
| `INSERT ... OUTPUT INSERTED.id` | `INSERT ... RETURNING id` | |
| `SCOPE_IDENTITY()`, `@@IDENTITY` | `RETURNING id` | `lastval()` — на сессию, опасен при нескольких последовательностях |
| `@@ROWCOUNT` | `GET DIAGNOSTICS v = ROW_COUNT` | только в PL/pgSQL |
| `MERGE ...` | `INSERT ... ON CONFLICT ... DO UPDATE` или `MERGE` (PG 15+) | `ON CONFLICT` требует уникального индекса |
| `UPDATE t SET ... FROM s WHERE ...` | `UPDATE t SET ... FROM s WHERE ...` | синтаксис совпадает, семантика соединения — проверить |
| `DELETE TOP (1000) FROM t` | `DELETE FROM t WHERE ctid IN (SELECT ctid FROM t LIMIT 1000)` | для порционной чистки |
| `TRUNCATE TABLE t` | `TRUNCATE TABLE t RESTART IDENTITY` | сброс последовательностей — явно |
| `SET IDENTITY_INSERT t ON` | `OVERRIDING SYSTEM VALUE` в `INSERT` | только для `GENERATED ALWAYS` |
| `SELECT ... FOR XML` | `SELECT ... FOR XML` нет | `xmlagg`, `xmlelement` |

### 3.6. Процедурный код

| T-SQL | PostgreSQL (PL/pgSQL) | Замечание |
|---|---|---|
| `DECLARE @v int; SET @v = 1;` | `DECLARE v integer := 1;` | |
| `SELECT @v = col FROM t` | `SELECT col INTO v FROM t` | |
| `IF ... BEGIN ... END` | `IF ... THEN ... END IF;` | |
| `WHILE ... BEGIN ... END` | `WHILE ... LOOP ... END LOOP;` | |
| курсор `DECLARE ... CURSOR` + `FETCH` | `FOR rec IN SELECT ... LOOP` | чаще курсор не нужен |
| `TRY ... CATCH` | `BEGIN ... EXCEPTION WHEN OTHERS THEN ... END;` | `SQLERRM`, `SQLSTATE` |
| `RAISERROR('msg',16,1)` | `RAISE EXCEPTION 'msg';` | `RAISE NOTICE` для сообщений |
| `THROW 50001,'msg',1` | `RAISE EXCEPTION 'msg' USING ERRCODE = '50001';` | |
| `EXEC(@sql)` | `EXECUTE format('... %I ...', ident);` | обязательны `quote_ident`/`format` |
| `sp_executesql @sql, N'@p int', @p = 1` | `EXECUTE sql USING p;` | |
| `OUTPUT`-параметры | `INOUT` / `OUT` параметры | |
| `RETURN 0` | `RETURN;` | код возврата не используется |
| `BEGIN TRAN` внутри `BEGIN TRAN` | `SAVEPOINT` + `ROLLBACK TO SAVEPOINT` | вложенных транзакций нет |
| `SET NOCOUNT ON`, `SET XACT_ABORT ON` | убрать | нет аналогов и нет необходимости |
| `DECLARE @t TABLE (...)` | `CREATE TEMP TABLE ... ON COMMIT DROP` | табличных переменных нет |
| скалярная UDF | функция `LANGUAGE sql`/`plpgsql` с `IMMUTABLE`/`STABLE` | метка волатильности влияет на планы |
| inline TVF | `RETURNS TABLE (...)` | |
| multi-statement TVF | `RETURNS TABLE` + `RETURN QUERY` | может стать медленнее, проверить план |

| linked server | `postgres_fdw`, `dblink` | |

| `IDENTITY` | `GENERATED BY DEFAULT AS IDENTITY` | перенос вручную (13.9) |
| `sp_rename` | `ALTER TABLE ... RENAME TO` | |
| `SET LANGUAGE` | `lc_messages`, `to_char` с локалью | |

## 4. Правила переписывания

1. **Один объект — один коммит.** Смешение «переписал процедуру и заодно поправил схему» мешает
   сверке.
2. **Сначала поведение, потом оптимизация.** Переписанный код проверяется на равенство результатов
   с MSSQL, и только потом оптимизируется.
3. **Никаких `SELECT *` в представлениях и процедурах** — после миграции порядок колонок может
   отличаться, а `INSERT ... SELECT *` сломается молча.
4. **Динамический SQL — только через `format()`/`quote_ident()`.** Склейка строк без
   экранирования в PostgreSQL такая же дыра, как в MSSQL.
5. **Обработка ошибок — по `SQLSTATE`.** Тексты сообщений не совпадают и не должны использоваться
   в логике.
6. **`EXCEPTION WHEN OTHERS` не должен глотать ошибку** без записи в лог: иначе данные «теряются
   тихо».
7. **Триггеры — идемпотентно.** Повторное применение строки не должно задваивать аудит.
8. **Функция без `IMMUTABLE`/`STABLE` не индексируется.** Если выражение используется в индексе,
   метка обязательна.

## 5. Как проверяется переписанный объект

| Проверка | Как |
|---|---|
| результат совпадает | тот же вход → тот же выход, включая `NULL` и пустые строки |
| граничные случаи | 0 строк, 1 строка, NULL в ключевых колонках, максимальные длины |
| ошибка воспроизводится | тот же нарушающий вход даёт ошибку с ожидаемым `SQLSTATE` |
| нет неявных приведений | `EXPLAIN` не показывает лишних `cast` на больших таблицах |
| нет блокировок дольше ожидаемого | тест двумя параллельными сессиями |
| права | объект создан владельцем-миграцией, приложение вызывает по гранту |

## Готово, когда

- [ ] рабочий список объектов заполнен, у каждого есть ответственный и статус;
- [ ] все объекты в статусе «проверен»;
- [ ] для каждой встреченной конструкции есть замена из таблицы (или обоснованное решение);
- [ ] динамический SQL переведён на `format`/`quote_ident`/`USING`;
- [ ] обработка ошибок работает по `SQLSTATE`, ретраи покрывают `40001`/`40P01`/`55P03`;
- [ ] проверены граничные случаи: NULL, пустые строки, максимальные длины, отсутствие строк;
- [ ] таблица замен дополнена конструкциями, которых не было в шаблоне (для следующего проекта).

## Типичные ошибки

| Симптом | Причина | Что делать |
|---|---|---|
| запрос возвращает другие строки | `LIKE` стал регистрозависимым | `ILIKE`/`citext`/collation (13.4) |
| длина строки «выросла» | `LEN` vs `length` с хвостовыми пробелами | `length(rtrim(s))` |
| `strpos` не находит | перепутан порядок аргументов | `strpos(строка, подстрока)` |
| процедура «молча» ничего не делает | `EXCEPTION WHEN OTHERS` без лога | логировать `SQLSTATE`/`SQLERRM`, не глотать |
| аудит задвоился | триггер идемпотентно не написан | проверить `NEW`/`OLD` и ключи аудита |
| `ON CONFLICT` не работает | нет уникального индекса по ключу конфликта | создать PK/уникальный индекс |
| динамический SQL ломается на кириллице | склейка без `quote_ident` | `format('%I', ...)` |
| после переписывания стало медленнее | потерян индекс или изменена волатильность функции | `EXPLAIN`, метки `IMMUTABLE`/`STABLE` |

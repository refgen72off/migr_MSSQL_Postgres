# 13.1 Инвентаризация источника

Инструкция к этапу 1 плана («Объём и критичность»). Результат этапа: заполненный инвентарь
объектов и объёмов, класс критичности системы, список объектов, которые придётся переносить
вручную, и согласованное решение «окно остановки записи» либо «стратегия дельты».

## 1. Подготовка

**Учётная запись на источнике — только чтение.** Минимальный набор прав:

| Право | Зачем |
|---|---|
| `db_datareader` на каждую БД | чтение данных при сверке и пилоте |
| `VIEW DEFINITION` на каждую БД | метаданные: `sys.objects`, `sys.columns`, `sys.sql_modules` |
| `VIEW DATABASE STATE` на каждую БД | DMV: `sys.dm_db_index_usage_stats`, `sys.dm_db_partition_stats` |
| `SQLAgentReaderRole` в `msdb` | список заданий и их шагов |
| `VIEW ANY DEFINITION` на экземпляре (по возможности) | `sys.server_principals`, `sys.sql_logins`, `sys.configurations` |
| `VIEW SERVER STATE` на экземпляре (по возможности) | `sys.dm_os_sys_info` (время старта, 13.1/13.3), серверные DMV раздела 6 инструкции 13.2 |
| чтение `msdb` (`db_datareader`, по возможности) | история бэкапов `msdb.dbo.backupset` (13.2, раздел 2) |

`sysadmin` не нужен и не выдаётся. Если выдать `VIEW ANY DEFINITION` нельзя — часть серверных
разделов (логины, конфигурация) снимает DBA источника на своей стороне и передаёт файлы.

Скрипт создания учётной записи выполняет DBA источника от имени `sysadmin`/`securityadmin`
(это разовая административная операция — сам миграционный логин дальше используется только
на чтение). Имя логина здесь — пример, замените на своё:

```sql
-- 00-create-reader-login.sql   (контекст: master; выполнять от sysadmin/securityadmin)
USE master;

-- 1. Логин. Если уже существует — шаг пропустить.
--    Пароль передавать из секретного хранилища или переменной, в скрипты не вшивать.
CREATE LOGIN migr_reader WITH PASSWORD = N'<сложный пароль>',
     CHECK_POLICY = ON,
     DEFAULT_DATABASE = [<БД>];

-- 2. Права уровня экземпляра («по возможности» из таблицы выше; нельзя — пропустить,
--    пострадавшие разделы снимает DBA источника). Гранты серверного скоупа выдаются
--    ТОЛЬКО в контексте master: если выполнять команды по частям, сначала USE master;
--    иначе ошибка «Permissions at the server scope can only be granted when the
--    current database is master».
GRANT VIEW SERVER STATE   TO migr_reader;
GRANT VIEW ANY DEFINITION TO migr_reader;

-- 3. Права на целевую БД
USE [<БД>];
CREATE USER migr_reader FOR LOGIN migr_reader;
ALTER ROLE db_datareader ADD MEMBER migr_reader;
GRANT VIEW DEFINITION    TO migr_reader;
GRANT VIEW DATABASE STATE TO migr_reader;

-- 4. msdb: история бэкапов (13.2, раздел 2) и задания Agent
USE msdb;
CREATE USER migr_reader FOR LOGIN migr_reader;
ALTER ROLE db_datareader      ADD MEMBER migr_reader;
ALTER ROLE SQLAgentReaderRole ADD MEMBER migr_reader;
```

Самопроверка выданных прав (выполняется тем же административным логином):

```sql
-- 00-verify-reader.sql
EXECUTE AS LOGIN = 'migr_reader';
SELECT * FROM fn_my_permissions(NULL, 'SERVER');     -- ожидается VIEW SERVER STATE, VIEW ANY DEFINITION
USE [<БД>];
SELECT * FROM fn_my_permissions(NULL, 'DATABASE');   -- ожидается SELECT, VIEW DEFINITION, VIEW DATABASE STATE
USE msdb;
SELECT * FROM fn_my_permissions(NULL, 'DATABASE');   -- ожидается SELECT (+ задания через SQLAgentReaderRole)
REVERT;
```

Замечания к скрипту:

- `ALTER ROLE ... ADD MEMBER` требует SQL Server 2012+; для более старых версий —
  `exec sp_addrolemember 'db_datareader', 'migr_reader'` (помечено как устаревшее).
- `CHECK_POLICY = ON` на Linux-сборках (включая контейнеры) принимается, но не enforced —
  сложность пароля обеспечивает владелец пароля, а не сервер.
- Удаление учётной записи после миграции — зеркальный скрипт `DROP USER`/`DROP LOGIN`
  на каждую БД из шагов 3–4, затем `DROP LOGIN` в `master`.

**Инструменты:** `sqlcmd` (входит в состав SQL Server или в `mssql-tools`), любой редактор для
чтения CSV.

**Куда складывать результат.** В каталог **вне репозитория**:
`C:\work\migr\<БД>\inventory\2026-11-18\`. Причина: репозиторий публичный, имена объектов,
серверов и учётных записей заказчика туда попадать не должны. В репозитории хранятся только
шаблоны и обезличенные примеры (см. раздел 15).

**Как запускать.** Все запросы — в контексте нужной БД (`USE [<БД>];`), кроме тех, где явно
указано `msdb` или серверный контекст.

```bat
sqlcmd -S <сервер> -d <БД> -E -i 01-passport.sql   -o 01-passport.csv -W -s ";" -w 4000
```

Флаг `-E` — Windows-аутентификация. Для SQL-аутентификации пароль передаётся переменной
окружения `SQLCMDPASSWORD` (не параметром `-P`: он останется в истории и в списке процессов).

Аптайм экземпляра важен: счётчики DMV (раздел 14) обнуляются при рестарте, и на свежем
экземпляре они бесполезны.

```sql
-- 02-databases.sql
SELECT d.name,
       d.recovery_model_desc,
       d.compatibility_level,
       d.collation_name,
       d.state_desc,
       d.is_read_only,
       d.snapshot_isolation_state_desc,
       d.is_read_committed_snapshot_on,
       d.is_published,
       d.is_subscribed,
       d.is_merge_published,
       d.is_distributor,
       d.is_broker_enabled,
       d.log_reuse_wait_desc,
       d.create_date
FROM sys.databases d
WHERE d.database_id > 4          -- без system-баз
ORDER BY d.name;
```

Флаги `is_published` / `is_subscribed` / `is_distributor` / `is_broker_enabled` сразу отвечают
на вопросы «есть ли репликация и Service Broker» — это отдельные виды работ, которых у
pgloader нет вовсе.

Размер файлов по базам (данные и лог отдельно):

```sql
-- 03-db-sizes.sql
DECLARE @sql nvarchar(max), @name sysname;
DECLARE @out TABLE (db sysname, data_mb decimal(18,1), log_mb decimal(18,1));

DECLARE cur CURSOR LOCAL FAST_FORWARD FOR
    SELECT name FROM sys.databases WHERE database_id > 4 AND state_desc = 'ONLINE';

OPEN cur;
FETCH NEXT FROM cur INTO @name;
WHILE @@FETCH_STATUS = 0
BEGIN
    SET @sql = N'SELECT ' + QUOTENAME(@name,'''') + N' AS db,
        CAST(SUM(CASE WHEN type_desc = ''ROWS'' THEN size END) / 128.0 AS decimal(18,1)) AS data_mb,
        CAST(SUM(CASE WHEN type_desc = ''LOG''  THEN size END) / 128.0 AS decimal(18,1)) AS log_mb
        FROM ' + QUOTENAME(@name) + N'.sys.database_files;';
    INSERT INTO @out EXEC sp_executesql @sql;
    FETCH NEXT FROM cur INTO @name;
END
CLOSE cur; DEALLOCATE cur;

SELECT * FROM @out ORDER BY data_mb DESC;
```

## 3. Объекты по типам

```sql
-- 04-objects-by-type.sql
SELECT s.name AS schema_name, o.type_desc, COUNT(*) AS objects
FROM sys.objects o
JOIN sys.schemas s ON s.schema_id = o.schema_id
WHERE o.is_ms_shipped = 0
  AND o.type IN ('U','V','P','PC','FN','IF','TF','TR','SO','SN','TT','AF','FS','FT','SQ')
GROUP BY s.name, o.type_desc
ORDER BY o.type_desc, s.name;
```

Расшифровка кодов: `U` таблица, `V` представление, `P` процедура, `PC` CLR-процедура,
`FN`/`IF`/`TF` функции, `TR` триггер, `SO` последовательность, `SN` синоним, `TT` табличный тип,
`AF`/`FS`/`FT` CLR-агрегат/скаляр/табличная функция, `SQ` очередь Service Broker.

Число таблиц и представлений — база для сверки структуры после миграции, число процедур,
функций и триггеров — оценка ручной работы (этап 12).

## 4. Таблицы: строки и размер

```sql
-- 05-tables-rows-size.sql
SELECT s.name AS schema_name,
       t.name AS table_name,
       SUM(p.rows)                                                   AS row_count,
       CAST(SUM(a.total_pages) * 8 / 1024.0 AS decimal(18,1))         AS total_mb,
       CAST(SUM(a.used_pages)  * 8 / 1024.0 AS decimal(18,1))         AS used_mb,
       CAST(SUM(a.data_pages)  * 8 / 1024.0 AS decimal(18,1))         AS data_mb,
       CAST(SUM(CASE WHEN a.type = 2 THEN a.total_pages ELSE 0 END) * 8 / 1024.0
            AS decimal(18,1))                                        AS lob_mb,    -- LOB-хранилище (a.type = 2)
       CAST(SUM(CASE WHEN a.type = 3 THEN a.total_pages ELSE 0 END) * 8 / 1024.0
            AS decimal(18,1))                                        AS row_overflow_mb,
       CASE WHEN MAX(i.index_id) = 0 THEN 'heap' ELSE 'clustered' END AS structure,
       t.create_date,
       t.modify_date
FROM sys.tables t
JOIN sys.schemas s            ON s.schema_id  = t.schema_id
JOIN sys.indexes i            ON i.object_id  = t.object_id AND i.index_id IN (0,1)
JOIN sys.partitions p         ON p.object_id  = t.object_id AND p.index_id = i.index_id
JOIN sys.allocation_units a   ON a.container_id = p.partition_id
WHERE t.is_ms_shipped = 0
GROUP BY s.name, t.name, t.create_date, t.modify_date
ORDER BY total_mb DESC;
```

`SUM(p.rows)` по секциям даёт корректное число строк таблицы. Для точной сверки на этапах 10 и
12 всё равно понадобится `COUNT_BIG(*)` (раздел 13.3): значение из `sys.partitions` считается по
метаданным и для memory-optimized таблиц не работает. Колонка `structure` фиксирует таблицы без
кластерного индекса (heap) — «кластерность» в PostgreSQL не переносится: heap и clustered
переносятся одинаково; `lob_mb` — объём LOB-хранилища (обещание раздела 2.1 плана).

## 5. Индексы

```sql
-- 06-indexes.sql
SELECT s.name AS schema_name,
       t.name AS table_name,
       i.name AS index_name,
       i.type_desc,
       i.is_unique,
       i.is_primary_key,
       i.is_unique_constraint,
       i.has_filter,
       i.filter_definition,
       i.fill_factor,
       i.is_disabled,
       STUFF((SELECT ', ' + c.name + CASE WHEN ic.is_descending_key = 1 THEN ' DESC' ELSE '' END
              FROM sys.index_columns ic
              JOIN sys.columns c ON c.object_id = ic.object_id AND c.column_id = ic.column_id
              WHERE ic.object_id = i.object_id AND ic.index_id = i.index_id
                AND ic.is_included_column = 0
              ORDER BY ic.key_ordinal
              FOR XML PATH(''), TYPE).value('.', 'nvarchar(max)'), 1, 2, '') AS key_columns,  -- TYPE+.value: без экранирования &, <, >
       (SELECT COUNT(*) FROM sys.index_columns ic2
        WHERE ic2.object_id = i.object_id AND ic2.index_id = i.index_id
          AND ic2.is_included_column = 1)                     AS included_columns
FROM sys.indexes i
JOIN sys.tables t  ON t.object_id = i.object_id
JOIN sys.schemas s ON s.schema_id = t.schema_id
WHERE t.is_ms_shipped = 0
  AND i.type > 0
ORDER BY s.name, t.name, i.index_id;
```

Что искать в результате:

- `has_filter = 1` — фильтрованные индексы, прямого аналога нет (частичный индекс PostgreSQL
  как замена, но условие нужно переписать);
- `included_columns > 0` — `INCLUDE` не переносится, нужен либо `INCLUDE`-аналог через
  покрывающий индекс, либо отказ от него;
- `type_desc` не `CLUSTERED`/`NONCLUSTERED` — columnstore, XML, spatial, hash-индексы
  memory-optimized таблиц: отдельный список ручных решений.

## 6. Ограничения: ключи, FK, CHECK, DEFAULT

```sql
-- 07-constraints.sql
SELECT 'PK/UK' AS kind, s.name AS schema_name, t.name AS table_name,
       kc.name AS constraint_name, kc.type_desc
FROM sys.key_constraints kc
JOIN sys.tables t  ON t.object_id = kc.parent_object_id
JOIN sys.schemas s ON s.schema_id = t.schema_id
WHERE t.is_ms_shipped = 0

UNION ALL

SELECT 'FK', s.name, tp.name, fk.name,
       fk.delete_referential_action_desc + '/' + fk.update_referential_action_desc
FROM sys.foreign_keys fk
JOIN sys.tables tp ON tp.object_id = fk.parent_object_id
JOIN sys.schemas s ON s.schema_id = tp.schema_id

UNION ALL

SELECT 'CHECK', s.name, t.name, cc.name,
       CASE WHEN cc.is_disabled = 1 THEN 'disabled' ELSE 'enabled' END + ' / ' +
       CASE WHEN cc.is_not_trusted = 1 THEN 'not trusted' ELSE 'trusted' END
FROM sys.check_constraints cc
JOIN sys.tables t  ON t.object_id = cc.parent_object_id
JOIN sys.schemas s ON s.schema_id = t.schema_id

UNION ALL

SELECT 'DEFAULT', s.name, t.name, dc.name, dc.definition
FROM sys.default_constraints dc
JOIN sys.tables t  ON t.object_id = dc.parent_object_id
JOIN sys.schemas s ON s.schema_id = t.schema_id

ORDER BY kind, schema_name, table_name;
```

`is_not_trusted = 1` означает, что ограничение есть, но данные им не проверялись: при переносе
такое ограничение может не пройти валидацию — это заранее известный риск, а не сюрприз.

## 7. Идентичность и последовательности

```sql
-- 08-identity-sequences.sql
SELECT s.name AS schema_name, t.name AS table_name, c.name AS column_name,
       ic.seed_value, ic.increment_value,
       IDENT_CURRENT(QUOTENAME(s.name) + '.' + QUOTENAME(t.name)) AS ident_current
FROM sys.identity_columns ic
JOIN sys.tables  t ON t.object_id = ic.object_id
JOIN sys.columns c ON c.object_id = ic.object_id AND c.column_id = ic.column_id
JOIN sys.schemas s ON s.schema_id = t.schema_id
WHERE t.is_ms_shipped = 0

UNION ALL

SELECT SCHEMA_NAME(sq.schema_id), '(sequence)', sq.name,
       sq.start_value, sq.increment, sq.current_value
FROM sys.sequences sq
ORDER BY schema_name, table_name;
```

`IDENT_CURRENT` — значение на текущий момент; именно оно должно совпасть с `last_value`
последовательности в PostgreSQL после `setval` (этап 9).

## 8. Типы данных: «зоопарк»

```sql
-- 09-types-usage.sql
SELECT t.name AS type_name, COUNT(*) AS columns_used
FROM sys.columns c
JOIN sys.types t   ON t.user_type_id = c.user_type_id
JOIN sys.tables tb ON tb.object_id = c.object_id AND tb.is_ms_shipped = 0
GROUP BY t.name
ORDER BY columns_used DESC;
```

Колонки, из-за которых обычно и начинается ручная работа:

```sql
-- 10-types-detail.sql
SELECT s.name AS schema_name, tb.name AS table_name, c.name AS column_name,
       t.name AS type_name,
       c.max_length, c.precision, c.scale, c.is_nullable,
       c.collation_name, c.is_identity, c.is_computed
FROM sys.columns c
JOIN sys.tables  tb ON tb.object_id = c.object_id AND tb.is_ms_shipped = 0
JOIN sys.schemas s  ON s.schema_id = tb.schema_id
JOIN sys.types t    ON t.user_type_id = c.user_type_id
WHERE t.name IN ('datetimeoffset','rowversion','timestamp','sql_variant','geometry',
                 'geography','hierarchyid','image','ntext','text','xml','varbinary',
                 'datetime','datetime2','money','smallmoney','uniqueidentifier','bit')
   OR c.max_length = -1                 -- varchar(max) / varbinary(max)
ORDER BY t.name, s.name, tb.name, c.column_id;
```

Сверять с таблицей соответствий типов из раздела 4.3 плана. Особое внимание:
`datetimeoffset` (нужен `timestamptz`, но смещение в исходных данных может отличаться от
серверного часового пояса), `rowversion` (переносить нечем — исключение или `bytea`),
`geography`/`hierarchyid` (`bytea` по умолчанию = потеря структуры, нужно решение),
`sql_variant` (аналога нет).

## 9. Collation по колонкам

```sql
-- 11-collation-mismatch.sql
SELECT s.name AS schema_name, tb.name AS table_name, c.name AS column_name,
       c.collation_name, DATABASEPROPERTYEX(DB_NAME(),'Collation') AS db_collation
FROM sys.columns c
JOIN sys.tables  tb ON tb.object_id = c.object_id AND tb.is_ms_shipped = 0
JOIN sys.schemas s  ON s.schema_id = tb.schema_id
WHERE c.collation_name IS NOT NULL
  AND c.collation_name <> DATABASEPROPERTYEX(DB_NAME(),'Collation')
ORDER BY s.name, tb.name, c.column_id;
```

Колонки с «своим» collation — кандидаты на явный `COLLATE` в PostgreSQL и на отдельные тесты
сравнения. Отдельно фиксируется, чувствительна ли collation к регистру (`_CI_` в имени) — это
источник ловушки из раздела 7.2 плана.

## 10. Представления, триггеры, синонимы

```sql
-- 12-programmability.sql
SELECT 'indexed view' AS kind, s.name AS schema_name, v.name AS object_name,
       CAST(NULL AS nvarchar(4000)) AS detail          -- тип фиксируем явно для UNION
FROM sys.views v
JOIN sys.schemas s ON s.schema_id = v.schema_id
WHERE OBJECTPROPERTY(v.object_id,'IsIndexed') = 1

UNION ALL

SELECT 'view with schemabinding', s.name, v.name, NULL
FROM sys.views v
JOIN sys.schemas s ON s.schema_id = v.schema_id
WHERE OBJECTPROPERTY(v.object_id,'IsSchemaBound') = 1

UNION ALL

SELECT 'trigger (DML)', s.name, tr.name,
       OBJECT_NAME(tr.parent_id) + N' / ' +
       CASE WHEN tr.is_instead_of_trigger = 1 THEN N'INSTEAD OF' ELSE N'AFTER' END + N' / ' +
       CASE WHEN tr.is_disabled = 1 THEN N'disabled' ELSE N'enabled' END
FROM sys.triggers tr
JOIN sys.tables t  ON t.object_id = tr.parent_id
JOIN sys.schemas s ON s.schema_id = t.schema_id

UNION ALL

-- DDL-триггеры уровня БД: parent_id = 0, в sys.tables их нет
SELECT 'trigger (DDL)', SCHEMA_NAME(tr.schema_id), tr.name,
       tr.parent_class_desc + N' / ' +
       CASE WHEN tr.is_disabled = 1 THEN N'disabled' ELSE N'enabled' END
FROM sys.triggers tr
WHERE tr.parent_class_desc = 'DATABASE'

UNION ALL

SELECT 'synonym', SCHEMA_NAME(schema_id), name, base_object_name
FROM sys.synonyms
ORDER BY kind, schema_name, object_name;
```

Серверные DDL-триггеры (уровня сервера) в этом запросе не видны: они живут в `sys.server_triggers`
и запрашиваются из `master`. Если инвентаризация этапа 1 нашла linked servers — проверить и их.

Триггеры — самый дорогой пункт: в MS SQL они срабатывают на инструкцию и видят `inserted`/
`deleted` как набор строк, в PostgreSQL триггер вызывается на строку (или на инструкцию, но с
другими `NEW`/`OLD`). Один триггер MS SQL = один или несколько триггеров PL/pgSQL плюс, возможно,
переписанная логика. Текст триггеров и процедур выгружается через `sys.sql_modules` (этап 4).

## 11. Интеграции: linked servers, jobs, SSIS, репликация, Service Broker, CLR, Full-Text

```sql
-- 13-integrations.sql
SELECT 'linked server' AS kind, name AS object_name,
       ISNULL(product,'') + ' / ' + ISNULL(data_source,'') AS detail
FROM sys.servers
WHERE is_linked = 1

UNION ALL

SELECT 'assembly (CLR)', name, permission_set_desc
FROM sys.assemblies
WHERE is_user_defined = 1

UNION ALL

SELECT 'fulltext index', OBJECT_NAME(object_id), CAST(is_enabled AS varchar(10))
FROM sys.fulltext_indexes

UNION ALL

SELECT 'service queue', name, CAST(is_activation_enabled AS varchar(10))
FROM sys.service_queues
WHERE is_ms_shipped = 0
ORDER BY kind, object_name;
```

Задания Agent — отдельный запрос в `msdb` (искать и по имени БД, и по имени схемы):

```sql
-- 14-agent-jobs.sql   (контекст: msdb)
USE msdb;
SELECT j.name AS job_name, j.enabled, sc.name AS schedule_name,
       s.step_id, s.step_name, s.subsystem, s.command
FROM dbo.sysjobs j
LEFT JOIN dbo.sysjobschedules js ON js.job_id = j.job_id
LEFT JOIN dbo.sysschedules  sc  ON sc.schedule_id = js.schedule_id
LEFT JOIN dbo.sysjobsteps   s   ON s.job_id = j.job_id
                               AND s.command LIKE '%<БД>%'   -- подставить имя БД/схемы
ORDER BY j.name, s.step_id;
```

Фильтр по `command` стоит в `ON`, а не в `WHERE`: в `WHERE` он превратил бы `LEFT JOIN` во
внутренний и задания без шагов потерялись бы. Поиск по подстроке неполон: шаги, ссылающиеся на
БД через `USE` или `sp_executesql`, этим фильтром не находятся — полный разбор текста шагов
делается на этапе 4.

Задания — не переносятся: в PostgreSQL их заменяют `pg_cron`, systemd-таймеры или
планировщик приложения. Решение принимается на этапе 4, здесь только перечень и текст команд.

Пакеты SSIS: каталог `SSISDB` (`catalog.packages`) либо устаревшее хранение в
`msdb.dbo.sysssispackages` — оба варианта фиксируются как «внешняя интеграция, требует
отдельного плана».

## 12. Особые таблицы: temporal, in-memory, сжатие, файловые группы

```sql
-- 15-special-tables.sql
SELECT 'temporal' AS kind, SCHEMA_NAME(schema_id) AS schema_name, name, temporal_type_desc
FROM sys.tables WHERE temporal_type <> 0

UNION ALL

SELECT 'memory-optimized', SCHEMA_NAME(schema_id), name, durability_desc
FROM sys.tables WHERE is_memory_optimized = 1

UNION ALL

SELECT 'compression', SCHEMA_NAME(t.schema_id), t.name, p.data_compression_desc
FROM sys.partitions p JOIN sys.tables t ON t.object_id = p.object_id
WHERE p.index_id IN (0,1) AND p.data_compression <> 0
GROUP BY t.schema_id, t.name, p.data_compression_desc
ORDER BY kind, schema_name, name;
```

Temporal-таблицы (system-versioned) в PostgreSQL прямого аналога не имеют: нужна пара таблиц
плюс триггеры или расширение — это ручная работа. Memory-optimized таблицы переносятся как
обычные, но теряют поведение и требуют пересчёта нагрузки. Сжатие в PostgreSQL решается на
уровне хранилища (`TOAST`, `pglz`/`lz4`), отдельного переноса не требует.

## 13. Права, роли, логины

```sql
-- 16-permissions.sql
SELECT pr.name AS principal, pr.type_desc, pe.class_desc, pe.permission_name,
       pe.state_desc,
       OBJECT_SCHEMA_NAME(pe.major_id) AS object_schema,
       OBJECT_NAME(pe.major_id)        AS object_name

-- 17-roles.sql
SELECT r.name AS role_name, m.name AS member_name, m.type_desc
FROM sys.database_role_members rm
JOIN sys.database_principals r ON r.principal_id = rm.role_principal_id
JOIN sys.database_principals m ON m.principal_id = rm.member_principal_id
WHERE r.is_fixed_role = 0          -- db_datareader и прочие фиксированные роли не показываем

```

## 14. Нагрузка и зависимости приложений

```sql
-- 19-usage-stats.sql
SELECT OBJECT_SCHEMA_NAME(i.object_id)  AS schema_name,
       OBJECT_NAME(i.object_id)         AS table_name,
       SUM(s.user_seeks + s.user_scans + s.user_lookups) AS reads,
       SUM(s.user_updates)                                AS writes,
       MAX(s.last_user_seek)            AS last_read,
       MAX(s.last_user_update)          AS last_write
FROM sys.dm_db_index_usage_stats s
JOIN sys.indexes i ON i.object_id = s.object_id AND i.index_id = s.index_id
WHERE s.database_id = DB_ID()
GROUP BY i.object_id
ORDER BY reads DESC, writes DESC;
```

Ограничения метода, которые надо озвучить заказчику:

- счётчики обнуляются при рестарте экземпляра — сверяйтесь с `instance_start_time` из раздела 2;
- это счётчики обращений к индексам, а не бизнес-критичность: таблица без обращений может быть
  архивной, а может быть таблицей, к которой ходят раз в месяц закрытия периода;
- если на источнике включён Query Store (SQL Server 2016+), данные надёжнее:

```sql
-- 20-query-store.sql
SELECT TOP (20) q.query_id, qt.query_sql_text,
       SUM(rs.count_executions) AS executions,
       SUM(rs.avg_duration * rs.count_executions) / NULLIF(SUM(rs.count_executions),0) AS avg_duration_us
FROM sys.query_store_query q
JOIN sys.query_store_query_text qt ON qt.query_text_id = q.query_text_id
JOIN sys.query_store_plan p        ON p.query_id = q.query_id
JOIN sys.query_store_runtime_stats rs ON rs.plan_id = p.plan_id
GROUP BY q.query_id, qt.query_sql_text
ORDER BY executions DESC;
```

Класс критичности (A — остановка недопустима, B — окно до N часов, C — окно выходного дня)
определяется не запросами, а разговором с владельцем системы: результат разговора фиксируется
в `inventory.md` одной строкой на систему, с именем того, кто подтвердил.

## Типичные ошибки

| Симптом | Причина | Что делать |
|---|---|---|
| `sys.dm_db_index_usage_stats` почти пуст | экземпляр недавно перезапущен | сверить `sqlserver_start_time`, использовать Query Store |
| `sys.objects` показывает сотни объектов | не отфильтрован `is_ms_shipped` | фильтр обязателен, иначе инвентарь бесполезен |
| число строк не совпало после миграции на 1–2 | берётся `sys.partitions`, а не `COUNT_BIG` | для сверки использовать точный счётчик (13.3) |
| не видны задания Agent | запрос выполнен не в `msdb` или нет прав | `USE msdb` + `SQLAgentReaderRole` |
| не видны логины | нет `VIEW ANY DEFINITION` | запросить у DBA источника, не повышать свои права |
| инвентарь содержит имена серверов и учётных записей в git | каталог инвентаря внутри репозитория | держать выгрузки вне репозитория (раздел 1) |

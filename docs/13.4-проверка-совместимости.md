## 2. Поиск проблемных конструкций

Прогон по выгруженным файлам (PowerShell) даёт количественную картину, а не «кажется, много»:

```powershell
$patterns = [ordered]@{
  'триггеры: inserted/deleted'      = '\b(inserted|deleted)\b'
  'динамический SQL'                = '\bEXEC(UTE)?\s*\(|\bsp_executesql\b'
  'курсоры'                         = '\b(DECLARE\s+\w+\s+CURSOR|FETCH\s+NEXT)\b'
  'TRY/CATCH'                       = '\bBEGIN\s+TRY\b'
  'RAISERROR/THROW'                 = '\b(RAISERROR|THROW)\b'
  'MERGE'                           = '\bMERGE\s+'
  'OUTPUT clause'                   = '\bOUTPUT\s+(INSERTED|DELETED)\.'
  'IDENTITY/SCOPE_IDENTITY'         = '\b(SCOPE_IDENTITY|@@IDENTITY|IDENT_CURRENT)\b'
  'TOP / OPTION / NOLOCK'           = '\b(TOP\s*\(|OPTION\s*\(|NOLOCK)\b'
  'APPLY'                           = '\b(CROSS|OUTER)\s+APPLY\b'
  'PIVOT/UNPIVOT'                   = '\b(PIVOT|UNPIVOT)\b'
  'FOR XML / FOR JSON'              = '\bFOR\s+(XML|JSON)\b'
  'временные таблицы'               = '#{1,2}\w+'
  'кросс-базовые имена (db.schema)' = '\b\w+\.\w+\.\w+\b'
  'OPENROWSET/OPENQUERY'            = '\bOPEN(ROWSET|QUERY|XML)\b'
  'иерархия/XML-методы'             = '\.(value|nodes|query|exist)\s*\('
}

Get-ChildItem 'C:\work\migr\<БД>\modules' -Filter *.sql | ForEach-Object {
  $text = Get-Content $_.FullName -Raw
  foreach ($k in $patterns.Keys) {
    if ($text -match $patterns[$k]) {
      [pscustomobject]@{ File = $_.Name; Construct = $k }
    }
  }
} | Group-Object Construct | Sort-Object Count -Descending |
    ForEach-Object { "{0,-34} {1}" -f $_.Name, $_.Count }
```

Отдельно — зависимости объектов (что от чего ломается при удалении/переименовании):

```sql
-- 42-dependencies.sql
SELECT OBJECT_SCHEMA_NAME(d.referencing_id) AS from_schema,
       OBJECT_NAME(d.referencing_id)        AS from_object,
       ISNULL(OBJECT_SCHEMA_NAME(d.referenced_id), d.referenced_schema_name) AS to_schema,
       ISNULL(OBJECT_NAME(d.referenced_id), d.referenced_entity_name)        AS to_object,
       d.referenced_class_desc

WHERE d.referencing_id IS NOT NULL
ORDER BY from_schema, from_object;
```

## 3. Типы данных: решения, а не «на усмотрение»

Ниже — рабочие решения для проекта. Колонка «решение» переносится в `cast-rules.txt`.

| MSSQL | Решение в PostgreSQL | Почему и что проверить |
|---|---|---|
| `datetime`, `datetime2` | по умолчанию pgloader даёт `timestamptz` | если приложение хранило «локальное время без зоны», `timestamptz` сдвинет значения при выводе. Решение проекта: `timestamp` без зоны (`type datetime to timestamp`, `type datetime2 to timestamp`), если в данных нет зоны; иначе оставить `timestamptz` и зафиксировать TZ сервера |
| `datetimeoffset` | `timestamptz` | смещение сохраняется при конвертации; проверить строки с разными смещениями |
| `smalldatetime` | `timestamp` | ничего не теряется: `smalldatetime` сам хранит только минуты, секунды будут `:00` |
| `time`, `date` | `time`, `date` | совпадает |
| `money`, `smallmoney` | `numeric(19,4)` | 4 знака — родная точность `money`; `smallmoney` — тоже 4 |
| `float(53)`, `float(24)` | `double precision`, `real` | сравнения только с допуском, суммы по `float` не сверяются |
| `numeric(p,s)`, `decimal(p,s)` | `numeric(p,s)` (`keep typemod`) | без `keep typemod` масштаб теряется |
| `bit` | `boolean` | `NOT NULL` переносить явно |
| `tinyint` | `smallint` | диапазон шире; при необходимости `CHECK (col BETWEEN 0 AND 255)` |
| `char(n)`, `nchar(n)` | `char(n)` (`keep typemod`) | паддинг пробелами сохраняется |
| `varchar(n)`, `nvarchar(n)` | `varchar(n)` (`keep typemod`) | по умолчанию pgloader отбрасывает длину и даёт `text` |
| `varchar(max)`, `nvarchar(max)`, `ntext`, `text` | `text` | границу `max` отдельным правилом по `precision = -1` |
| `binary(n)`, `varbinary(n/max)`, `image` | `bytea` | `image` устарел, но встречается |
| `uniqueidentifier` | `uuid` | порядок сортировки иной: `ORDER BY` по `uuid` не совпадёт с MSSQL — проверить запросы |
| `xml` | `text` (по умолчанию) либо `xml` | `xml` даёт валидацию и XPath-функции; выбор влияет на код |
| `rowversion` / `timestamp` | **не переносить** | это счётчик версий строки, не дата. Решение: колонку исключить; при необходимости «оптимистичных блокировок» заменить на `xmin` |
| `sql_variant` | `jsonb` + колонка типа, либо `text` | прямого аналога нет, нужен разбор по фактическим значениям |
| `hierarchyid` | `text` (материализованный путь) или `ltree` | `bytea` от pgloader бесполезен для запросов |
| `geography`, `geometry` | PostGIS `geometry`/`geography`, если расширение доступно в Tantor; иначе WKT в `text` | `bytea` от pgloader — потеря структуры, только как временный вариант |
| пользовательский тип (alias) | домен (`CREATE DOMAIN`) поверх базового типа | ограничения типа переносятся в домен |
| табличный тип (TT) | составной тип или временная таблица в коде | используется в параметрах процедур |

Готовые правила `CAST` (вставляются в загрузочный файл, 13.7). Типы, для которых у pgloader
**нет правил по умолчанию** (`date`, `time`, `datetimeoffset`, `smalldatetime`, `text`, `ntext`,
`image`), обязаны быть в этом блоке — иначе колонка не загрузится:

```
CAST type nvarchar  to varchar keep typemod,    -- nvarchar(max) не имеет typemod и попадает сюда же: varchar без длины (эквивалент text)
     type nchar     to char    keep typemod,
     type varchar   to varchar keep typemod,
     type char      to char    keep typemod,
     type numeric   to numeric keep typemod,
     type decimal   to numeric keep typemod,
     type money     to numeric drop typemod,    -- точную (19,4) задаёт ALTER после загрузки (13.9): грамматика CAST typemod в цели не принимает
     type smallmoney to numeric drop typemod,
     type datetime  to timestamp drop typemod,
     type datetime2 to timestamp drop typemod,
     type smalldatetime to timestamp drop typemod,
     type datetimeoffset to timestamptz drop typemod,   -- правила по умолчанию нет; смещение сохраняется
     type date      to date,
     type time      to time,
     type text      to text,                    -- устаревшие LOB-типы: правил по умолчанию нет
     type ntext     to text,
     type image     to bytea
```

Примечания к блоку:

- `rowversion` — правила нет и не нужно: колонка исключается из загрузки по решению таблицы
  выше. Правило на имя `rowversion` и не сработало бы — в каталоге MSSQL (`sys.types`) этот тип
  называется `timestamp`;
- правило `when (= precision -1)` для `nvarchar(max)` бесполезно: у `(max)`-колонок pgloader
  не видит typemod, условие никогда не выполняется — реальные `(max)`-колонки обрабатывает
  следующее правило (`varchar` без длины).

Синтаксис `{ drop | keep } typemod`, guard `when (= precision -1)` и форма `column table.col`
подтверждены документацией pgloader. Правило `column` переопределяет `type` для одной колонки:

```
     column dbo.documents.body to text drop typemod
```

Последнюю строку (`rowversion`) применять только если колонку решено сохранить как текст; иначе
её исключают из загрузки и переносят решение в список ручных работ.

## 4. Идентификаторы: длина, регистр, зарезервированные слова

```sql
-- 43-identifier-risks.sql
-- Сравнения — только в бинарной коллейции: при CI-коллейции базы 'Orders' = 'orders'
-- и детекторы молча возвращают пустой результат. utf8_bytes — байтовая длина имени
-- в UTF-8 (лимит PostgreSQL — 63 байта, а не символа: 40 кириллических символов = 80 байт).
SELECT s.name AS schema_name, o.name AS object_name, o.type_desc,
       LEN(o.name) AS name_length,
       b.utf8_bytes,
       CASE WHEN b.utf8_bytes > 63 THEN 'too long (utf-8 bytes)' END AS too_long,
       CASE WHEN o.name COLLATE Latin1_General_BIN2 <> LOWER(o.name) COLLATE Latin1_General_BIN2
            THEN 'mixed case' END AS mixed_case,
       CASE WHEN o.name COLLATE Latin1_General_BIN2 LIKE '%[^a-zA-Z0-9_]%'
            THEN 'needs quoting' END AS special_chars
FROM sys.objects o
JOIN sys.schemas s ON s.schema_id = o.schema_id
CROSS APPLY (SELECT SUM(CASE WHEN UNICODE(SUBSTRING(o.name, n, 1)) <  128 THEN 1
                             WHEN UNICODE(SUBSTRING(o.name, n, 1)) < 2048 THEN 2
                             ELSE 3 END) AS utf8_bytes
             FROM (SELECT TOP (LEN(o.name)) ROW_NUMBER() OVER (ORDER BY (SELECT NULL)) AS n
                   FROM sys.all_objects) AS nums) AS b
WHERE o.is_ms_shipped = 0
  AND (b.utf8_bytes > 63
       OR o.name COLLATE Latin1_General_BIN2 <> LOWER(o.name) COLLATE Latin1_General_BIN2
       OR o.name COLLATE Latin1_General_BIN2 LIKE '%[^a-zA-Z0-9_]%')
ORDER BY utf8_bytes DESC;
```

Отдельно — имена колонок, совпадающие с зарезервированными словами PostgreSQL (`user`, `order`,
`limit`, `offset`, `group`, `window`, `authorization`, `current_user`, `between`, `cast`, `do`,
`freeze`, `isnull`, `notnull`, `session_user`, `verbose`, `analyse`). Проверка:

```sql
-- 44-reserved-names.sql
SELECT s.name AS schema_name, t.name AS table_name, c.name AS column_name
FROM sys.columns c
JOIN sys.tables t  ON t.object_id = c.object_id
JOIN sys.schemas s ON s.schema_id = t.schema_id
WHERE c.name IN ('user','order','limit','offset','group','window','authorization','between',
                 'cast','do','freeze','isnull','notnull','session_user','verbose','analyse','check')
ORDER BY schema_name, table_name, column_name;
```

Правила проекта:

- pgloader по умолчанию приводит имена к нижнему регистру (`downcase identifiers`). Если
  приложение обращается к `Orders` без кавычек — это работает; если с кавычками и в смешанном
  регистре — сломается. Решение фиксируется до загрузки: `downcase identifiers` (проще для
  приложения) либо `quote identifiers` (сохраняет регистр, но требует правки всех запросов).
- Имена длиннее 63 байт усекаются молча — либо переименование через
  `ALTER TABLE NAMES MATCHING 'old' ... RENAME TO 'new'`, либо явный список переименований для
  приложения.
- Колонки с пробелами и спецсимволами требуют кавычек в каждом запросе — кандидаты на
  переименование в рамках проекта, а не «потом».

## 5. Кодировка и collation

- База-источник в однобайтовой кириллице (`cp1251`) и целевая в `UTF8` — данные конвертируются,
  но проверить надо и содержимое, и длину: `nvarchar(50)` в UTF-8 занимает до 50 символов, а
  `varchar(50)` в cp1251 — до 50 байт; после `keep typemod` ограничение может стать строже, чем
  было по факту. Проверка максимальных длин — в снимке (13.3).
- Нечувствительность к регистру (`_CI_`) в MSSQL против регистрозависимого сравнения в
  PostgreSQL: варианты решения — `citext` (расширение, тип колонки), `ILIKE` в запросах, ICU-
  collation с `und-u-ks-level2`, функциональные индексы `lower(col)`. Внимание: `level1`
  нечувствителен и к **диакритике** (`ё` = `е`), что противоречит тесту ниже; для аналога
  `_CI_AS_` нужен `level2`.
- Провайдер локали целевой БД выбирается один раз (13.5): `ICU` даёт предсказуемую сортировку
  кириллицы, `libc` — зависимость от локалей ОС.

Тестовый набор запросов, который должен дать одинаковый результат на обеих СУБД, собирается
заранее: поиск по `'иванов'`, по `'Иванов'`, сортировка справочника, `LIKE '%ё%'`,
`UPPER/LOWER` для кириллицы, сравнение `'ё'` и `'е'`.

## 6. DEFAULT и computed columns

```sql
-- 45-defaults-and-computed.sql
SELECT s.name AS schema_name, t.name AS table_name, c.name AS column_name,
       dc.definition AS default_definition
FROM sys.default_constraints dc
JOIN sys.columns c ON c.object_id = dc.parent_object_id AND c.column_id = dc.parent_column_id
JOIN sys.tables t  ON t.object_id = dc.parent_object_id
JOIN sys.schemas s ON s.schema_id = t.schema_id
ORDER BY schema_name, table_name, column_name;

SELECT s.name AS schema_name, t.name AS table_name, c.name AS column_name,
       c.definition, c.is_persisted, c.is_nullable
FROM sys.computed_columns c
JOIN sys.tables t  ON t.object_id = c.object_id
JOIN sys.schemas s ON s.schema_id = t.schema_id
ORDER BY schema_name, table_name, column_name;
```

Типовые замены дефолтов:

| MSSQL | PostgreSQL |
|---|---|
| `GETDATE()`, `GETUTCDATE()` | `now()`, `now() AT TIME ZONE 'UTC'` |
| `SYSDATETIME()`, `SYSUTCDATETIME()` | `clock_timestamp()`, `clock_timestamp() AT TIME ZONE 'UTC'` |
| `NEWID()` | `gen_random_uuid()` (ядро PG 13+, расширение не нужно) |
| `''` (пустая строка как «нет значения») | чаще всего `NULL`: решение продуктовое, не техническое |
| `0`, `(0)` для числовых | `0` |
| `SUSER_SNAME()`, `ORIGINAL_LOGIN()` | `current_user`, `session_user` |
| `NEXT VALUE FOR seq` | `nextval('seq')` |

`computed columns` переносятся как `GENERATED ALWAYS AS (expr) STORED` (PostgreSQL поддерживает
только `STORED`). Неперсистентные computed columns становятся либо `STORED`-колонками (проще), либо
вычисляются в представлении/приложении (дешевле по записи). Выражение переписывается вручную:
функции MSSQL и PostgreSQL различаются (см. 13.13).

## 7. Identity и последовательности

В документации pgloader для MSSQL нет правила, превращающего `IDENTITY` в `serial`/`identity`
(в отличие от MySQL `auto_increment`). Практический вывод: колонка переносится как обычный
`integer`, а идентичность создаётся отдельно — на этапе 9.

Решение проекта (фиксируется здесь, выполняется в 13.9):

- `GENERATED BY DEFAULT AS IDENTITY` — если приложение иногда вставляет явные значения
  (типичный случай при переносе исторических данных);
- `GENERATED ALWAYS AS IDENTITY` — если явные вставки запрещены и это проверено по коду;
- отдельная последовательность — только если идентификатор не привязан к одной колонке.

Что проверить в источнике: `seed`, `increment`, негативный шаг, `IDENTITY_INSERT` в коде,
использование `SCOPE_IDENTITY()`/`@@IDENTITY` (замена — `RETURNING id`).

## 8. Ограничения: семантика, а не только наличие

| Тема | MSSQL | PostgreSQL | Что делать |
|---|---|---|---|
| UNIQUE и NULL | уникальный индекс допускает **один** NULL | допускает много NULL | `UNIQUE NULLS NOT DISTINCT` (PG 15+), иначе поведение меняется |
| FK-действия | `CASCADE`/`SET NULL`/`NO ACTION`/`SET DEFAULT` | те же, кроме `RESTRICT` как отдельного | переписать `NO ACTION` → `RESTRICT`, если нужна немедленная проверка |
| `NOT FOR REPLICATION` | есть | нет | не переносится, зафиксировать в списке |
| отключённые/недоверенные ограничения | `is_disabled`, `is_not_trusted` | нет аналога | включить и валидировать на этапе 9 |
| CHECK и NULL | `CHECK` пропускает NULL | так же | поведение совпадает |
| уникальность с фильтром | фильтрованный индекс | частичный индекс | переносится вручную, условие переписать |
| имя ограничения | объект `sys.objects`, уникально **в схеме** | CHECK/DEFAULT — достаточно уникально в таблице; PK/UNIQUE создают индексы, уникальные в схеме | при переносе MSSQL → PG конфликтов не возникает (обратное направление — да) |

## 9. Триггеры, представления, синонимы, временные таблицы

- **Триггеры**: MSSQL — на инструкцию, с наборами `inserted`/`deleted`; PostgreSQL — `FOR EACH
  ROW` (по умолчанию) или `FOR EACH STATEMENT` с `transition tables` (`REFERENCING NEW TABLE AS`).
  Один триггер MSSQL обычно превращается в функцию + триггер PL/pgSQL; порядок срабатывания
  задаётся именем (`CREATE TRIGGER a_...`), а не числом порядка.
- **INSTEAD OF** на представлениях в PostgreSQL реализуется через `INSTEAD OF`-триггер — без
  изменений в логике приложения.
- **Индексированные представления** → материализованные представления (`REFRESH
  MATERIALIZED VIEW`), уникальный индекс на матвью обязателен для `CONCURRENTLY`.
- **`ORDER BY` во представлении**: PostgreSQL допускает его безусловно (в отличие от MSSQL, где
  `ORDER BY` во view требует `TOP`), но не гарантирует порядок строк для внешних запросов —
  сортировку переносить в запрос приложения.
- **Синонимы** (`sys.synonyms`) → представление с тем же именем в нужной схеме либо настройка
  `search_path`.
- **Временные таблицы** (`#temp`, `##temp`): `CREATE TEMP TABLE` живёт в сессии; глобальных
  временных таблиц нет — общий кэш заменяется обычной таблицей с ключом сессии или `UNLOGGED`.
- **Три части имени** (`db.schema.table`) и кросс-базовые запросы: в PostgreSQL нет — либо
  `postgres_fdw`, либо перенос логики в приложение (решение фиксируется здесь).

## 10. Порядок и зависимости

Зафиксировать в `compatibility.md`:

1. Схемы: `dbo` → `public` (или своя схема), прочие схемы переносятся как есть.
2. Переименования таблиц/колонок (список «было → стало») — вход для правки приложения (13.13).
3. Порядок создания: таблицы → данные → индексы → FK/CHECK → триггеры/код (решение 7.5 плана).
4. Объекты, которые нельзя создать до данных (уникальные индексы на грязных данных, CHECK на
   исторических нарушениях) — с причиной и планом исправления данных.

## Типичные ошибки

| Симптом | Причина | Что делать |
|---|---|---|
| после загрузки даты сдвинуты на часы | `datetime` → `timestamptz` и TZ сервера | правило `to timestamp` или фиксация TZ обеих сторон |
| строки обрезаны на границе длины | дефолт `drop typemod` → `text`, затем ручное `varchar(n)` | `keep typemod` в `CAST` |
| приложение не находит таблицу `Orders` | `downcase identifiers` по умолчанию | согласовать стратегию регистра до загрузки, а не после |
| миграция падает на дублях уникального индекса | в MSSQL NULL допускался один, а данных больше | `NULLS NOT DISTINCT` или чистка данных |
| CHECK-ограничение не создаётся | нарушение в исторических данных | `NOT VALID` + план исправления, валидация в 13.9 |
| триггер срабатывает N раз вместо одного | построчная семантика PostgreSQL | `FOR EACH STATEMENT` + `REFERENCING`, либо перенос логики в код приложения |
| `identity` после загрузки начинает с 1 | pgloader не создаёт identity для MSSQL | создать identity/последовательность и `setval` (13.9) |
